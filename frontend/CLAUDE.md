# Frontend workspace notes — the desk v2 shell

## Design rules — read `PHILOSOPHY.md` first

[`PHILOSOPHY.md`](./PHILOSOPHY.md) is the design rulebook for this layer — the generative
`DP*` principles (classify by who a thing serves, the customization path is the build
path, judge the API by what an author writes, a contribution adds rather than edits).
It also inherits [`../ui/PHILOSOPHY.md`](../ui/PHILOSOPHY.md) (`FP1`–`FP3`) and
[frappe-ui's](https://github.com/frappe/frappe-ui/blob/main/PHILOSOPHY.md) (`P1`–`P14`)
in full. Walk them before drafting or refactoring, and cite by ID in reviews (`DP1`,
`FP2`, `P3`). The notes below are operational specifics — the design *rules* live in
PHILOSOPHY.md, not here.

## Running the tests

`frontend/package.json` does not exist in a clean checkout. It is **generated by
`bench build`** from `package.base.json` plus each contributing app's dependencies, and
is gitignored (`.gitignore:205`) along with `manifest.json`, `node_modules`,
`auto-imports.d.ts`, `components.d.ts` and `frappe/public/frontend`.

So the suite does not run until you make one:

```bash
cp frontend/package.base.json frontend/package.json
yarn --cwd frontend install --frozen-lockfile
yarn --cwd frontend test:run
```

That is exactly what CI does (`.github/workflows/frontend-tests.yml`). The **base** file
is the correct input, not a `bench build`-generated one: `yarn.lock` was resolved from
`package.base.json` alone, and no test needs anything an app contributes. Baseline is
**18 files / 328 tests**, under `recordPage/tests/`, `shell/tests/` and
`navigation/tests/`.

**`vitest.config.js` runs with `css: { postcss: {} }`, and that is not cosmetic.**
`postcss.config.js` loads `tailwind.config.js`, which reads `manifest.json` at module
scope — the very file this whole section is about not having. Any test that imports a
frappe-ui component with a `<style>` block sends the transform through `vite:css` and the
run dies on a clean clone with a postcss error naming a `.vue` file nobody wrote a test
about. It also runs the **contributions plugin**, over a manifest stated inline rather
than read: frappe's eight navigation item renderers are contributions like any other, and
a test that mocked `virtual:frappe/contributions` would exercise the mock rather than the
door.

Two things to know:

- **`frontend/yarn.lock` is committed on purpose** and the reason is written at
  `.gitignore:213-216`: `enforce_singletons` compares declared *ranges*, so without a
  lock two benches with identical `hooks.py` can still resolve different transitive
  versions.
- **`vitest.config.js` is separate from `vite.config.js` deliberately** — the latter calls
  `readManifest()` at module scope, and `manifest.json` does not exist on a fresh clone or
  in CI. Its `include` glob is `src/**/tests/*.test.ts`; a test file anywhere else, or one
  directory deeper, **silently does not run**.

## Formatting: `.js` and `.vue` are formatted, `.ts` is not

This is the trap that costs the most diff noise. Pre-commit runs **prettier v2.7.1** with
`types_or: [javascript, vue, scss]` (`.pre-commit-config.yaml`). **TypeScript is not in
that list, and there is no prettier config anywhere in the repo.** The root
`.editorconfig` mandates tabs (`indent_size 4`, `max_line_length 99`) for
`*.py,*.js,*.vue,*.css,*.scss,*.html` — `.ts` is not listed there either.

Consequences, all of them load-bearing:

- **`.js` and `.vue` here are tab-indented** and prettier will enforce it. Match it.
- **No formatter of any kind runs over `.ts`.** That is why `frontend/src/**/*.ts` is
  genuinely mixed: the shell and plumbing files (`main.ts`, `boot.ts`, `router/*`,
  `contributions/*`) are 2-space with **single** quotes; most of `recordPage/**` is
  2-space with **double** quotes; a handful (`surface.ts`, `context.ts`, `iconClasses.ts`
  and their tests) are tabs.
- **Do not run `npx prettier --write` over a `.ts` file here.** Prettier is not
  *declared* by this workspace, but it is *installed*: `frappe-ui` depends on
  `prettier@^3.3.2`, which `frontend/yarn.lock` resolves to **3.9.6**. So `npx prettier`
  quietly runs that local binary — a whole major ahead of the **2.7.1** pre-commit
  enforces, and never reached by the hook anyway, since its `types_or` excludes
  TypeScript. With `.editorconfig` not covering `.ts` either, it rewrites the file to its
  own defaults: a one-line change becomes a whole-file diff that CI never asked for.
  `ui/CLAUDE.md`'s blanket "always run prettier on changed files" is written for that
  package's `.vue` components and does **not** transfer to `.ts` in here.

**The rule: match the file you are editing.** Consistency within a file beats consistency
across the tree, because nothing mechanical is going to enforce the latter.

## Never run `yarn build` by hand

`bench build` runs the shell build (`frappe/build.py:127`) and overrides two settings that
`frontend/vite.config.js` deliberately sets for the bench path: `outDir` and
`emptyOutDir: false`. A bare `yarn build` writes **straight into the served tree** and
leaks stale hashed chunks — `frappe/build.py` cites 98 files and 14 MB after a handful of
builds. `bench build` instead builds to a staging directory and rename-swaps it.

Related: `build_shell` **returns silently if `frontend/package.base.json` is missing**
(`frappe/build.py:140-141`). That guard is on the *committed* half on purpose — guarding
on the generated `package.json` would make a fresh clone build nothing and then serve
"Shell Not Built" at every `/apps` URL. `bench build --app X` reaches the shell build and
is accepted-and-ignored rather than refused.

When the shell is genuinely not built, `ShellPage` throws a "Shell Not Built" page and
returns **200, never 404** — a 404 loses the asset preloads.

## Imports: one alias, and a package that is not aliased

- **`@/` → `frontend/src`.** That is the *only* alias, in both `vite.config.js` and
  `tsconfig.json`.
- **`@framework/ui` is not an alias** — it is a real dependency, `link:../ui`. Aliasing it
  was rejected on purpose (`frontend/vite.config.js:63-67`): aliasing a package to a
  directory bypasses its `exports` map and breaks every subpath import. `resolve.dedupe`
  was rejected for the same class of reason — it silently picks a winner. Singleton
  identity is established earlier, by `enforce_singletons`, which is what
  `preserveSymlinks: true` then preserves.

So **`ui/package.json`'s `exports` map is load-bearing for every import from here.** Deep
imports like `@framework/ui/components/Fields/rowIdentity` match no named key; they fall
through the final wildcard entry, `"./*": { "import": "./src/*" }`. If a subpath import
mysteriously fails to resolve, look at that map before anything else.

## Where a contribution lives

Five paths, and nothing is parsed from file *contents* — app, module, doctype and kind all
fall out of the path. Enumerated in both languages, in `frappe/shell/manifest.py` and
`frontend/plugin/contributions.js`:

| Path | Kind |
| --- | --- |
| `<app>/<module>/doctype/<scrubbed>/frontend/record.js` | record page, owning app |
| `<app>/<module>/doctype/<scrubbed>/frontend/list.js` | list, owning app |
| `<app>/<module>/custom/<scrubbed>/record.js` | record page, *foreign* doctype |
| `<app>/<module>/frontend/pages/<slug>.js` | a standalone page |
| `<app>/<module>/navigation_item_type/<scrubbed>/frontend/item.js` | a navigation item kind |

- **The `frontend/` segment in the page path is load-bearing** — `<module>/page/` is desk
  v1's Page doctype and `templates/pages/` is website templates.
- **The doctype name is read from the doctype's own JSON**, not title-cased from the
  folder: `crm_deal` → `CRM Deal`, not `Crm Deal`. Names are indexed from *every* app on
  the bench, not just contributing ones, because a `custom/` folder can name a doctype
  owned by an app that contributes nothing — otherwise the contribution would bundle,
  register, and silently never run.
- **An app whose *only* contribution is an item kind still reaches the bundle.** Whether an
  app is compiled in at all is `contributes()`, which globs exactly this table — so a path
  missing from it means the app's files are never bundled and its kind never registers,
  while its type record arrives at `bench migrate` regardless.
- **A contribution file with no default export is dropped with a `console.warn`, never a
  throw.** `registry.ts` is imported by `main.ts` before anything renders, so one app's
  typo must not fail the mount bench-wide. If your contribution "isn't running", check the
  console for that warning first.
- **Run order is per-doctype**: the owning app first, then the site's `app_order`.
  Ownership is structural, derived from which folder the file is in, with no registry
  lookup.

`frontend/src/contributions/registry.ts` is the seam. Its own comment says it is
deliberately tiny and that its size is the argument — keep it that way (`DP2`).

## Things that look wrong and are deliberate

Do not "fix" these:

- **`frontend/index.html` has no boot island**, no `__FRONTEND_ROUTE__`, no
  `__SOCKETIO_PORT__` and no import map. It is supposed to look under-populated.
- **`frappeui()` is called with `jinjaBootData: false` and `buildConfig: false`, and no
  `frontendRoute`** (`vite.config.js:43-48`). Turning any of them back on is a regression.
- **The router cannot be a module-scope singleton** — boot must resolve first, because the
  router's base comes from boot (`main.ts`). Contributions register before the router's
  first resolution.
- **`createRecordPage.ts` exempts the `doc` getter from the read-only rule**, and hands
  `router` straight through as the single exception. The file says in a comment not to
  delete the member and not to hand a second one through on its precedent.
- **`generated.ts` defines 4 routes for any number of doctypes** — `doctype` is a param,
  and `view`/`layout`/`from` are query params by decision.
- **The shared library list is `SINGLETONS` (`frappe/shell/manifest.py:22`)** — `vue`,
  `vue-router`, `frappe-ui`, `@framework/ui`, `reka-ui`, `dompurify` — enforced at build
  time and documented nowhere else. For the `frappe` app itself, deps are read from
  `frontend/package.base.json`, **not** `frappe/package.json`, which is desk v1's esbuild
  stack.
- **`package.base.json` pins `resolutions: { vite }`** because vitest declares a wide vite
  range and yarn would otherwise nest a second copy. `vite` is not in `SINGLETONS`, so
  nothing else catches it.
